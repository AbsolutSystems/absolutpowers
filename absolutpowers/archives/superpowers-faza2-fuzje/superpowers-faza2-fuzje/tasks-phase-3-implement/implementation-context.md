- Step O2 model routing (new): 3 named implementer tiers — transcription/cheapest (`haiku`, complete ready-to-transcribe code in phase file), standard (`sonnet`, integration/multi-file/`Risk: low|medium`, **and the fallback when code completeness is ambiguous**), most-capable (`opus`, `Risk: high`). `phase-review` = explicit model scaled to diff size/risk (rule stated in O2; the actual `phase-review` dispatch call in O4 still has no `model=` param — that wiring is Phase 5's job). `review-implementation` = always `opus` (rule stated in O2; actual O6 dispatch call still unwired — Phase 5's job). All three `implementation-worker` dispatch examples in O2 body now carry explicit `model=` (`opus`/`haiku`/`sonnet`).
- Step O2 "Before spawning the worker" now starts with a MUST bullet: record BASE = `git rev-parse HEAD` in the target project **before** dispatching the worker (not after). Storage location (ledger line) is explicitly deferred to Phase 3 — Phase 2 only mandates the step + rationale (avoids silent `HEAD~1` fallback in `review-package`).
- Ledger finalized (Phase 3): a new `### Durable Progress (ledger)` section sits between the "Path note" paragraph and `### Step O1`. Ledger file path: `progress.md` beside the phase directory (`./absolutpowers/feature/tasks-{slug}/progress.md`, or the epic-nested equivalent) — committed, not gitignored, NOT `.superpowers/sdd/`.
