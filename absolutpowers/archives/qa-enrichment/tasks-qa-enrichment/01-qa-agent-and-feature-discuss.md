## Tasks

### Task 1: Create QA Enrichment Agent
**Status:** completed

**Create:**
- `claude/agents/qa-enrichment.md`

**Requirements:**
- Frontmatter: `name: qa-enrichment`, `description` explaining QA enrichment role, `model: sonnet`, `tools: [Read, Glob, Grep, Bash, Edit]`
- Agent reads the planning doc path provided in the prompt
- Agent reads codebase: existing test files, CI config, test utilities, test patterns
- Agent appends `## Acceptance Criteria` section to the planning doc with three subsections:
  - `### Happy path` — main success scenarios
  - `### Edge cases` — boundary conditions, empty data, invalid input, race conditions
  - `### Security` — auth, injection, input validation
- Each AC formatted as `- AC-N: [behavioral description]` with sequential numbering starting at AC-1
- AC rules enforced in agent prompt:
  - Behavioral and user-facing (not "file exists", not "method returns X")
  - Zero implementation details (zero file paths, zero method signatures, zero class names)
  - Verifiable as true/false
  - Numbered `AC-N:` for stable pipeline reference
- Agent returns a summary of added AC count and categories
- Follow agent frontmatter pattern from `claude/agents/review-plan.md`

**Example:**
```yaml
---
name: qa-enrichment
description: >
  QA enrichment agent that analyzes a planning document and codebase
  to generate behavioral Acceptance Criteria. Appends AC section to
  the planning doc with happy path, edge case, and security criteria.
model: sonnet
tools:
  - Read
  - Glob
  - Grep
  - Bash
  - Edit
---
```
